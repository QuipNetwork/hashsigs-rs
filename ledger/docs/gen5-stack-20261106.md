# Gen5 wallet stack reduction — 2026-11-06

The operator authorized three steps: reduce the wallet's stack use, run the
emulator regressions, and take one focused physical creation measurement in
the separate HW Check app. The earlier capacity-four creation measurement
left only 1,640 bytes of stack headroom, below the unchanged 4,096-byte target.

This changes normal SHRINCS Lab to 0.2.2 and HW Check to 0.1.1. The profile,
capacity four, derivation bytes, wire formats, authenticated NVM layout, and
three-write commit order are unchanged. Signing remains disabled. This work
does not establish the cause of the earlier stall/reset incident.

## Implementation

Explicit non-inlined boundaries keep startup/reload, verification, creation,
generation, and installation scratch out of the always-live command loop.
Generation returns before installation allocates serialization/readback
buffers. The normal build has fewer callers than the diagnostic build, so LTO
previously inlined generation even when the diagnostic build kept it separate;
both ELFs were inspected after the change.

The 480-byte public ABI buffer now remains in a boxed allocation across
validation/load/install returns, avoiding repeated inline array copies. Only
public data moved; secret storage and zeroization are unchanged. The app also
retains the NBGL spinner across command handling so its borrowed text remains
alive until the next screen replaces it.

Disassembly shows these local frame allocations. They exclude saved registers
and nested calls; measured high-water marks below are the resource evidence.

## Physical measurement

The single physical creation sample **passed** on the same Gen5 and fresh,
unfunded test wallet used earlier that day. LedgerOS 1.1.1, MCU 8.1.2, and
bootloader 7.1.2 had been read during that day's preceding investigation; they
were not queried again during this focused run. The operator disabled
auto-lock and confirmed the unlocked home screen before installation.

The first installation attempt returned `5501` on the first protected script
command, before uploading the candidate. Its log is retained as `install.log`.
At the operator's request, installation was retried; `install-retry.log` ends
successfully. This replaced only the disposable HW Check installation. The
operator opened 0.1.1 manually and approved one creation. Normal 0.2.2 has not
been installed on the device.

The recorded command was `reproduce.py create --app-version 0.1.1
--expected-elf /out/hw-check.elf --output /out/physical-create.json`, through
the archived Docker image with network disabled and only USB node
`/dev/bus/usb/005/031` exposed. The HID computation deadline was 120 seconds,
with a 450-second outer process bound to include human approval. The timed
operation excludes review, starts with the one-use execution token, and
includes derivation, complete hybrid generation, progress/event handling,
three NVM writes, and the response. Later public readback is outside the timer.

The after-snapshot completed at **17:05:18 UTC**. Timing and resource checks
all passed; the runner closed normally with no outstanding requests.

## Remaining acceptance boundaries

The physical creation stack target is now met in HW Check 0.1.1. This does not extend
the earlier ephemeral capacity-4,096 benchmark into a persistent signer.
In-flight flash interruption, erase isolation/order guarantees, watchdog
thresholds, final uninstrumented hardware acceptance, and the unresolved reset
incident remain separate gates. No signing or recovery implementation was
added, and no key/counter history is reconstructed after reinstall.
